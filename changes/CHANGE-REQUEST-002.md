# 变更请求 002 · 规则裁决修订（胜负时序 / 平票重投 / 平局兜底）

> 提出日期：2026-11-17
> 提出人：用户（在 RFCS.md 的 C-6 与 RUL-1~10 复核中逐条拍板）
> 评估基线：`RULES.md` v1.0 §6、`RFCS.md` v2.1、`RFCs/RFC-001 ~ RFC-004`
> 决策状态：**4 项全部已由用户决定并落地**

---

## 0. 总体判断

这不是需求变化，是**规则裁决的修订**——PRD 的 FR 与 NFR 一条都不用改，但引擎的结算顺序、状态字段、以及三个 RFC 的验收标准要一起改。

起因有两处：

1. `RFCS.md` 的 **C-6**：`RULES.md` 的 RUL-1 说「猎人开枪带走最后一狼 → 好人胜」，而 `RFC-004` §2.7 说「同时达成 → 平局」。两份文档互相矛盾，必须裁决。
2. 用户在复核 RUL-1 ~ RUL-10 时，对其中三条给出了更明确的判断。

**根因**：RUL-1 的「技能结算先于胜负判定」与用户对「死先于枪」的直觉相反。

## 2. 逐项说明

### R-1 · 胜负判定先于死亡触发技能

**用户的理由（原话）**：「这个看起来是有先后顺序的，他得先死了，才能开枪，所以死的时候就已经是狼的胜利了，游戏就结束了，不存在他继续开枪的情况，只有游戏没结束的时候才能开枪。」

**新裁决**：

```
1. 应用死亡（狼刀 / 毒药 / 放逐），女巫解药在此步抵消击杀（RUL-8）
2. ★ 第一次胜负判定
   · 已分出胜负 → 对局结束，死亡触发技能不再结算
3. 结算死亡触发技能（猎人开枪）
4. ★ 第二次胜负判定
```

**为什么这个改动是对的**：

- 它**从根上消除了 C-6 的歧义**——狼胜条件成立的瞬间对局已结束，不可能出现「两阵营同时满足」。所以 RFC-004 里的 `draw`（同归于尽）分支和 §2.7 整节都可以删掉。
- 「死先于死带来的技能」在时序上是自洽的，不需要为「同时」发明一条优先级。
- 「开枪带走最后一狼翻盘」**仍然成立**，前提是猎人死时狼方尚未达成屠边。

**代价（必须知道）**：猎人在「自己就是最后一个神」的局面里**永远开不出枪**。这不是 bug，是新规则的必然结果。

**受影响的代码形状**：
- `checkWin` 变成被两个 RFC 共用的纯谓词，放在 RFC-002（引擎内核），但**判定时机与流程**仍归 RFC-004。这不构成 F6 的拆分——F6 仍由 RFC-004 拥有。

### R-2 · 平票重投不允许弃权

**用户的要求**：「RUL-2 改为只有并列者能被投。」

**新裁决**：重投的选项集**仅为并列最高票者本身**；不能弃权、不能投其他人。首轮投票仍允许弃权。

**理由**：重投的意义是「在并列者之间做选择」；允许弃权等于让重投再次沦为无结论。首轮保留弃权是为了让玩家能表达「不投」。

**与 PRD 的关系**：FR-6 原文是「平票时对并列最高票者重投一次，再次平票则该日无人出局」，并未提到弃权。原 RUL-2 加的「+ 弃权」是我自作主张，收窄后**更贴合 PRD 原文**，因此 PRD 不需要改。

### R-3 · 移除平局兜底

**用户的要求**：「不要平局，打到分出胜负」「不会存在永不终止的情况，因为拖的越久狼人越容易赢」。

**新裁决**：删除 RUL-10。对局不设人为的「连续 N 天无进展即平局」。

**终止性论证（用户判断成立，已验证）**：
- 女巫解药全局限一次；
- 解药用尽后，每夜必有狼刀死亡；
- 死亡单调累积，必然在某天达成某个屠边/屠城条件。

因此对局必然终止，不需要人为上限。人为上限反而会让「本来快赢的一局被强行判平」。

**受影响的代码形状**：`GameState.stalemateDays` 字段删除；RFC-004 的平局分支与对应验收标准删除。

### R-4 · RUL-8 保持不变

用户在复核时要求解释「解药和刀撞同一目标」。解释后未提出修改。

**含义**：女巫用解药救的正好是狼人今晚刀的那个人 → 该目标存活，当夜无人死亡。这不是两个效果竞争，而是**解药的定义本身**。RUL-8 只是把「解药必须先于击杀结算」写成规则，以免实现出「先判死再判解药」的 bug。

## 3. 冲突检查

### 3.1 与 RULES.md 自身

| 检查 | 结果 |
|---|---|
| 新 RUL-1 是否与 RUL-5（屠边只看存活）冲突 | 不冲突。RUL-5 决定的是「算不算达成」，新 RUL-1 决定的是「达成了什么时候判」 |
| 新 RUL-1 是否与 RUL-8 冲突 | 不冲突。RUL-8 作用在**死亡计算内部**，RUL-1 作用在**死亡之后** |
| 删除 RUL-10 是否破坏 NFR-2 的「必达终局」 | 不破坏。终止性由解药唯一 + 死亡单调累积保证（§2 R-3 的论证） |
| 新 RUL-2 是否与 RUL-9 冲突 | 不冲突。RUL-9 管「再次平票后怎么办」，RUL-2 管「重投时能投谁」 |
| 新 RUL-1 是否与 RUL-4（自曝后不投票）冲突 | 不冲突。自曝不产生死亡，不触发胜负判定 |

### 3.2 与 PRD / FEATURES

| 产物 | 是否需要改 | 说明 |
|---|---|---|
| `PRD.md` | **不需要** | FR-6 / FR-7 都没写死结算顺序与平局兜底；FR-15 与本次无关 |
| `FEATURES.md` | **需要改 F6** | 其 AC-4 写「双方同时满足条件时按 RA-1/RA-6 的裁决执行」——该情形已不可能出现 |
| `RULES.md` §6 | **需要改** | RUL-1 / RUL-2 / RUL-10 |
| `RFCS.md` | **需要改** | C-6 关闭；记录本次修订 |
| `RFC-001 ~ 004` | **需要改** | 见 §4 |
| `TEST-STRATEGY.md` | 尚不存在 | 无追溯成本 |
| `reviews/` | 尚不存在 | 无受影响评审 |
| 代码 | 尚不存在 | 无返工 |

## 5. 风险评估

| 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| 猎人在残局变弱，可能影响平衡 | 中 | 手感受影响，但不影响正确性 | 属于规则选择而非缺陷；若实测觉得过硬，可后续加「猎人被刀必能开枪」的变体规则（新变更） |
| 「必胜局被一枪翻盘」消失 | 低 | 戏剧性略降 | 仍然存在：只要猎人死时狼方尚未屠边，开枪就有意义 |
| 移除平局后极端长局 | 极低 | 玩家等待变长 | 终止性论证成立；引擎用随机输入测试兜底 |
| 忘记改 FEATURES 导致文档漂移 | 中 | 下游读到矛盾的验收标准 | 已在同一提交内改完 §4 的全部条目 |

## 6. 被否决的替代方案

| 方案 | 为什么否决 |
|---|---|
| 保持原 RUL-1（技能先于胜负），只把 RFC-004 的「平局」改成「好人胜」 | 用户明确指出时序上「死先于枪」；保持原样等于让「已死之人还能改变胜负」 |
| 保留平局作为「同时达成」的兜底 | 新时序下该情形不存在；保留死代码会成为永不执行的分支 |
| 把 `checkWin` 也放进 RFC-004，让 RFC-003 依赖它 | 会造成依赖倒挂（RFC-003 在 RFC-004 之前） |
| 让 RFC-003 不可枪 | 会丢掉 F8 的「猎人被毒不能开枪」这条验收的对照面 |
