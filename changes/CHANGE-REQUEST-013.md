# CHANGE-REQUEST-013 · 狼队投票改成「自由选择 + 确认」

**日期**：2026-11-23
**提出者**：用户（试玩反馈）
**状态**：**Accepted（2026-11-23）**

---

## 0. 一句话

狼队投票不是「按座位轮流发言式投票」，而是**自由投票**：任何狼随时可以选目标、改目标，
只有点了「确认」才锁定；其他狼能看到每个人当前选谁、有没有确认。

## 1. 变更分类

| 维度 | 结论 |
|---|---|
| 类型 | Feature Modification（RUL-13 的夜里投票流程） |
| 规模 | Large（引擎动作/事件、投影、编排并发、界面、提示词、测试） |
| 优先级 | Must（用户明确指出「狼人投票是自由的」） |

## 2. 新流程

### 2.1 规则（拟 RUL-15 / 修订 RUL-13）

1. 讨论阶段结束后进入投票；每名存活狼**随时**可以选目标，不需要等别人。
2. 选择分两步：
   - **选择（tentative）**：其他人能看到「N 号当前想投 M 号」，但未锁定；
   - **确认（confirm）**：锁定，不能再改。
3. 已确认的狼不能再改目标；未确认的可以反复改。
4. 投票阶段结束条件：所有存活狼都确认（可提前结束），或 10 秒到。
5. 计票只统计**已确认**的票；未确认的视为弃权（待用户确认）。
6. 10 秒到仍未确认：自动确认当前已选目标，或算弃权（待用户确认）。
7. 平票/重投沿用 RUL-13（重投不能弃权）。

### 2.2 引擎

| 项 | 设计 |
|---|---|
| `WOLF_VOTE` | 改成 `WOLF_VOTE_SELECT`：记录当前选择，可重复提交覆盖（未确认时） |
| `WOLF_VOTE_CONFIRM` | 锁定当前选择；已确认后再改 → 拒绝 |
| 事件 | `WOLF_VOTE_CAST`（带 `confirmed: boolean`）或拆成 SELECTED/CONFIRMED |
| 计票 | 只数 confirmed；全员 confirmed → 结算 |
| 超时 | 服务端替未确认者处理（见开放问题） |

### 2.3 编排

- 不再逐狼询问；讨论结束后，**每只 AI 狼独立**在投票阶段行动（脚本随机 + 确认；
  真实模型按讨论结论选择 + 确认），互相不阻塞。
- 玩家随时可选/确认；服务端广播票型（tentative + confirmed）。
- 10 秒兜底由服务端统一处理。

### 2.4 界面

- 投票面板显示每个人的状态：`想投 2 号（未确认）` / `已确认投 2 号`。
- 自己的按钮：选人后先变成「当前选择：2 号」，再点「确认」锁定。
- 确认后按钮禁用，显示「已确认」。

### 2.5 真实模型

- 进入讨论：根据已知情报发言（建议刀谁/附和别人）。
- **每当有狼发言**（AI 或玩家），重新思考一次：是否附和/提出新意见；
  若新结论与**自己最后一条发言**一致 → 不再重复发言。
- 投票阶段：按讨论得出的结论选择目标并确认。

## 3. 冲突检查

| 检查 | 结论 |
|---|---|
| RUL-13「每人一票、平票重投」 | 保留；只改「怎么投、何时锁定」 |
| RUL-14「10 秒投票超时弃权」 | 需要明确：有 tentative 时超时是确认还是弃权 |
| 现有 `WOLF_VOTE` 事件/测试 | 需要迁移（约 30+ 用例） |
| 顺序投票的实时票型 | 改为「自由投票 + 确认状态」，比现在更接近真实 |

## 4. 开放问题（需要拍板）

| ID | 问题 | 候选 |
|---|---|---|
| Q-013-1 | 10 秒到，有狼选了但没确认 | **(a) 自动确认当前选择** |
| Q-013-2 | 计票范围 | 只算已确认；超时自动确认后所有人都有确认票，所以不需要「未确认也算」 |
