# 变更请求 006 · 同一结算点同时满足两阵营胜利条件时判谁（C-27）

> 提出日期：2026-11-18
> 提出人：RFC-003 Round 3 评审（阻塞项 C-27）
> 评估基线：`RULES.md` §6（RUL-1 / RUL-5 / RUL-11）、`PRD.md` FR-6 / F8 / D40、`RFCS.md` C-6 / C-27、`RFCs/RFC-003` §2.3
> 决策状态：**已裁决并落地**（用户确认按真实规则取 B）

---

## 0. 总体判断

`RULES.md` §6 少了一条裁决，而这条缺口**能在一局完全合法的游戏里被触发**。

场景（屠边模式，终局前）：

> 场上只剩 **1 个神**、若干村民、**1 只狼**。那一夜：
> - 狼刀砍向最后一个神；
> - 女巫把毒药泼向最后一只狼。

结算后死亡批是「最后一个神 + 最后一只狼」。于是**同一瞬间**：

- 狼队的胜利条件成立（神已全部出局，屠边达成）；
- 好人侧的胜利条件成立（狼已全部出局）。

`checkWin` 现在先判「狼是否全灭」，于是**静默判好人胜**。

问题的性质不是「判错了」，而是**没有裁决就判了**：`RUL-1` 与 `RFCS.md` 的 C-6 只论证过「猎人开枪」这一种同时达成（结论是它不可能发生），**没有覆盖「狼刀 + 毒药」**。按 `ARCH-11`，引擎遇到 §6 未裁决的分支必须抛错，不许默认选一个——而现在它默认选了「好人胜」。

**查证结论：真实规则判狼人胜。** 这条原则叫「狼刀在先」，见 §3。所以现在的默认不只是「未裁决」，而是**与真实规则相反**。

**必须先裁决，再补测试**。裁决前改代码（无论改成哪种）都只是把「未记录的默认」换成「另一条未记录的默认」。

## 2. 为什么这不违反已做过的事

- **RUL-1**（胜负先于死亡触发技能）没有被推翻：它管的是「判定时机」，本 CR 管的是「同一时机里两个条件都成立时判谁」。RUL-1 的原文里那句「这一条同时消除了『两阵营同时达成』的歧义」只在**猎人开枪**的语境下成立——因为狼胜成立的瞬间对局已结束，猎人没机会开枪。**狼刀 + 毒药是同一批死亡**，不存在「先结束再触发」的顺序，那句话不适用。
- **RUL-10**（移除平局兜底）不冲突：本章要决定的是「谁赢」，不是「要不要允许平局」。若选平局方案才会与 RUL-10 的方向冲突（见 §6）。
- **`RFCS.md` C-6 已关闭**：它关闭的是「猎人开枪」那一种情形。本 CR 是在它未覆盖的地方补一条，不是重开它。

## 3. 候选与查证结论

### 真实规则怎么判（已查证）

**「狼刀在先」原则**：夜间结算后若同时满足两阵营胜利条件，**判狼人胜**。

- [百度百科·女巫](https://baike.baidu.com/item/%E5%A5%B3%E5%B7%AB/20587689)：当白天公布出局讯息后同时满足好人与狼人的胜利条件时（**例如狼人夜间完成屠边，女巫也毒死最后一名狼人**），视为**狼人获胜**，该规则又被称为「狼刀在先」原则。
- [知乎·简述狼人杀里经常误解的结算问题](https://zhuanlan.zhihu.com/p/625739586)：夜间全部技能均为**同时发动**，但夜间**优先结算狼人胜利条件**；「狼刀在先」**并不是文义上技能顺序的在先**，而是夜间结算胜利条件的优先。

因此 **方案 B 才是与真实规则一致的那个**。本 CR 初稿推荐的是方案 A（好人胜），理由是「狼全灭即失败、界面好解释」——那是从直觉与实现成本推出来的，不是从规则查出来的；查证推翻了它。

### 方案 B（推荐）· 狼人胜：「狼刀在先」原则

**规则措辞**：夜间结算后同时满足两阵营胜利条件时，**判狼人胜**（「狼刀在先」）。该原则只约束**夜间**——白天放逐不可能造成「好人侧被清空」，因此没有白天版本。

**理由**：

1. **与真实规则一致**（上面两条来源）。本项目的第一目标是「和真实狼人杀一致」，不是「最容易实现」。
2. **不靠「技能顺序」论证**：知乎那篇明确指出「狼刀在先不是技能顺序在先，而是夜间结算胜利条件的优先」。所以它不与 RUL-1 的「整批死亡后判一次」冲突——判定时机不变，只改「两个条件同时成立时判谁」。
3. **女巫的毒药照常结算**：她的合法行动不被丢弃（这一点与方案 D 的顾虑相同，B 不存在这个问题）。

**代价**：界面需要能解释「狼人获胜，但狼全部出局」。`GAME_ENDED.condition` 用 `night-wolf-priority`（或等价）说清楚，复盘里 `PLAYER_DIED` 的时间线也能对上。

### 方案 A · 好人胜（**不推荐**）

**否决理由**：与真实规则相反。「狼队被清空即失败」是个听上去合理、但**业界不采用**的直觉；本项目已有多条裁决（RUL-5 只看存活、RUL-11 毒药优先）都是以「真实规则优先于实现便利」为原则定的，这条不应例外。

### 方案 C · 平局

**否决**。`RUL-10` 刚刚移除了「人为的平局兜底」，理由是「本来快赢的一局被强行判平」。重新引入 draw 会把这条裁决的方向整个推翻，而且 `PLAYER_DIED` / `GAME_ENDED` 的 payload 里没有平局这个结果值（`result: 'wolf' | 'good'`）——改它要动 RFC-001 的契约。

### 方案 D · 显式未裁决错误（ARCH-11）

**否决**。它是「还不知道答案时的正确姿态」，但我们已经知道答案了；而且这条分支**在一局完全合法的游戏里可达**——抛错等于把正常对局打崩，与 Round 1 的 B1（合法输入崩溃）是同一类问题。

## 4. 冲突检查

### 4.1 与 RULES.md

| 规则 | 方案 A | 方案 B |
|---|---|---|
| **RUL-1** 胜负判定先于死亡触发技能 | 不冲突（管时机，不管同时达成） | 不冲突（B 不改变判定时机，只改同时成立时判谁） |
| **RUL-5** 屠边只看存活 | 不冲突 | 不冲突 |
| **RUL-11** 狼刀与毒药同目标 | 不冲突（那是同一座位，这是不同阵营的不同座位） | 不冲突 |
| **ARCH-11** 未裁决分支必须抛错 | 满足（裁决后不再是未裁决） | 满足（同） |

### 4.2 与 PRD / FEATURES

- **FR-6**（胜负判定）与 **F8 AC-4**：要求「规则歧义由 RULES 裁决」，本 CR 正是补这个。
- **F2 AC-4**（必达终局）：A/B 都终局，C 会引入第三种终局结果，D 会让合法对局无法终局。
- **D40**（歧义清单在 PRD，裁决权在 RULES）：本 CR 走 `/manage-changes` 正是 D40 的流程。

### 4.3 与既有 CR

- **CR-002** 修订过 RUL-1/RUL-2/RUL-10，并声称「两阵营同时达成不可能」。**它当时漏了「同一批死亡」这条路径**——本 CR 补的正是这个洞，不推翻它的任何裁决。

## 6. 风险评估

| 风险 | 影响 | 缓解 |
|---|---|---|
| 玩家觉得「狼全死了怎么还狼胜」 | 观感问题 | 这是「狼刀在先」原则的直接结果，属真实规则；`GAME_ENDED.condition` 写明 `night-wolf-priority`，复盘的时间线（刀口先于毒药）也能对上 |
| 有人把「狼刀在先」误解成「技能顺序在先」 | 后续 RFC 可能照着错的理由改判定时机 | RUL-12 的措辞要写明「只决定夜间同时成立时判谁，**不改变判定时机**」 |
| RFC-004 的白天天放逐会遇到同类情形 | 再来一次 CR | 本 CR 的 RUL-12 措辞要写成**模式无关、结算点无关**，白天直接复用 |
