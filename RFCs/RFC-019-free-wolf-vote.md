# RFC-019 · 狼队自由投票与确认

**Features**: F9, F10
**Depends on**: RFC-017, RFC-018
**Rules**: RUL-13, RUL-14, RUL-15
**Complexity**: Large

**Status**: Implemented（待评审）

---

## 1. 摘要

狼队投票从「按座位逐狼表态」改成**自由投票**：任何狼随时可选目标、改目标；
其他狼能看到「未确认」的意向，只有点「确认」才锁定。只统计确认票；全员确认立即结算；
10 秒到未确认者自动确认当前选择。

## 2. 设计

### 2.1 引擎

| 项 | 设计 |
|---|---|
| `WOLF_VOTE` | 选目标（tentative）；`confirmed` 省略时按 true 兼容旧调用；已确认者再选 → 拒绝 |
| `WOLF_VOTE_CONFIRM` | 锁定当前选择；没有选择 → 拒绝 |
| 事件 | `WOLF_VOTE_CAST { seat, target, confirmed }`、`WOLF_VOTE_CONFIRMED { seat }` |
| 计票 | 只数 `confirmed` 的票；全员 confirmed → 结算 |
| 重投 | 仍不能弃权；继承选择（未确认可改） |

### 2.2 编排

- 投票阶段不再逐狼询问：AI 各自独立选择并确认（脚本随机、模型按讨论结论）；
  玩家随时通过路由选择/确认；服务端等「全员确认或 10 秒」。
- 10 秒到：有选择 → 自动确认；无选择 → 弃权（重投则投并列者）。

### 2.3 界面

- 候选人按钮选中后显示「当前选择」；「确认」后锁定。
- 其他人的状态：`N 号想投 M 号（未确认）` / `N 号已确认投 M 号`。
- 票数统计只算确认票。

### 2.4 真实模型

- 讨论中，每当有狼发言就重新思考；结论与上一条自己的发言相同则不重复。
- 投票时按讨论结论选择并确认（一次动作完成选择+确认）。

## 3. 验收标准

1. 未确认的选择对其他狼可见，且可以改。
2. 确认后不能再改；其他狼看到「已确认」。
3. 只统计确认票；全员确认立即进入下一相位。
4. 10 秒到，有选择自动确认、无选择弃权。
5. 重投不能弃权，且只投并列者。
6. 玩家在投票阶段可自由选择/确认，不必等别人。
7. 脚本狼：讨论发言 + 5 秒准备 + 随机选择 + 确认。
8. 真实模型：按讨论结论投票；重复结论不刷屏。

## 4. Implementation Notes

| 项 | 结论 |
|---|---|
| 引擎 | `WOLF_VOTE { target, confirmed }`：未确认可改；`WOLF_VOTE_CONFIRM` 锁定；只数确认票；全员确认结算 |
| 兼容 | `confirmed` 省略按 true 处理，旧回放/旧测试仍能结算 |
| 编排 | 玩家可随时通过路由选择/确认；AI 依次选择+确认，票间有间隔；玩家确认后不再等待 |
| 超时 | 10 秒到：有选择自动确认；无选择弃权（重投投并列者） |
| 界面 | 「选 N 号」→「确认」；票型区分「想投（未确认）」与「已确认投」 |
| 真实模型 | 每当有狼发言就重新思考；同结论不重复；每个 AI 每夜最多 3 条 |

**偏离**：AI 票仍是服务端逐只提交（不是并行线程），但玩家可随时操作；这是为了保持引擎/存储的单写入路径。发言反应以 3 条为上限，避免模型互相附和无限循环。

**验证**：`pnpm test` 804 条、e2e 16 条、perf 3 条；typecheck/lint/format/build 全 0。

### 4.1 弃权票的显示（2026-11-23）

`WOLF_VOTE_CAST` 的 `abstain` 是引擎枚举，复盘与界面必须显示成「弃权」：
复盘时间线 `1 号弃权（狼队）`、票型 `1→弃权`，投票面板 `已确认弃权`。

### 4.2 选择不再自动确认（2026-11-23 修复）

路由曾把 `WOLF_VOTE`（选择）也通知给编排层，编排层当成「玩家给了目标」，
直接提交了一条 `confirmed: true` 的票。现在只有 `WOLF_VOTE_CONFIRM` 唤醒编排层，
选择保持未确认、可改。

### 4.3 玩家确认后不再放慢 AI 投票

`HOWL_WOLF_VOTE_DELAY_MS`（默认 1.2 秒）只用于玩家还是狼且**尚未确认**时，
让票型一条条出现、方便跟票。玩家确认后 AI 立即投完，夜晚继续进入预言家/女巫/结算，
不再人为等待。

### 4.4 AI 投票间隔可被玩家确认打断

原先 `HOWL_WOLF_VOTE_DELAY_MS` 用一次 `setTimeout` 睡满 1.2 秒，玩家在这期间确认也无法提前结束。
现在按 50ms 分段等待，一旦检测到玩家已确认/相位变化立即返回。
实测：确认 → 天亮弹窗约 60ms（客户端轮询也从 1s 降到 150ms）。

### 4.5 取消 AI 票的默认人为延迟（2026-11-23）

脚本 AI / 真实模型都没有必要人为等待：`HOWL_WOLF_VOTE_DELAY_MS` 默认 0，
只有显式设置时才用于演示「票型一条条出现」。玩家确认后自然立即推进。

### 4.6 竞态修复与实测（2026-11-23）

- 玩家确认可能发生在编排层「正阻塞等输入」的旧回合上：现在等待输入的同时轮询
  「是否已轮不到我/相位是否已变」，一旦变化立即返回，不再等 10 秒超时。
- 界面本地选中后「确认」立即可用；确认直接提交带目标的 `confirmed` 票（原子）。
- 客户端轮询 150ms。
- 真实浏览器整局实测：狼人 13.3s、预言家 9.0s、女巫 13.5s、猎人 13.5s、村民 3.6s；
  其中每夜约 5 秒的固定耗时来自**狼队讨论阶段脚本队友 5 秒后准备**，不是结算延迟。
